# PRD: 커뮤니티 게시판

Status: ready-for-agent

회원이 가입·로그인하고 글과 댓글을 작성하며 서로 추천하는 게시판. 자프링(Spring Boot 4.0.6, JDK 25) + 타임리프 기반 서버 렌더링 웹앱.

용어는 `CONTEXT.md`를 따른다(Recommendation, ViewCount, Member, Role, Author, Post, Comment, Reply). 삭제 정책은 `docs/adr/0001-soft-delete.md`를 따른다.

## Problem Statement

사용자는 글과 댓글로 소통하고, 마음에 드는 글·댓글에 호감을 표시하며, 인기 있는 글을 가늠할 수 있는 공간이 필요하다. 또한 본인이 쓴 글·댓글을 관리(수정·삭제)하고, 운영자는 부적절한 글·댓글을 정리할 수 있어야 한다.

## Solution

회원 가입·로그인 기반의 게시판을 제공한다. 회원은 글과 댓글(1단계 대댓글 포함)을 작성하고, 글·댓글에 추천(토글)을 표시할 수 있다. 글에는 조회수가 누적되어 관심도를 보여준다. 작성자는 본인 글·댓글을 수정·삭제할 수 있고, 관리자(ADMIN)는 모든 글·댓글을 정리할 수 있다. 삭제는 소프트 삭제로 처리되어 이력이 보존된다.

## User Stories

1. 비회원으로서, username·password·nickname으로 회원가입하여, 게시판에 참여하고 싶다.
2. 회원으로서, username·password로 로그인하여, 내 계정으로 활동하고 싶다.
3. 회원으로서, 로그아웃하여, 세션을 종료하고 싶다.
4. 회원으로서, 내 정보 페이지에서 nickname과 password를 수정하여, 내 표시 이름과 비밀번호를 관리하고 싶다.
5. 회원으로서, 내 정보 페이지에서 내 username을 확인하되 변경할 수 없어, 로그인 ID가 고정됨을 알고 싶다.
6. 방문자로서, 글 목록을 최신순·페이지 단위로 조회하여, 최근 글을 훑어보고 싶다.
7. 방문자로서, 글 상세를 열람하여, 글 내용과 달린 댓글을 보고 싶다.
8. 회원으로서, 제목·내용으로 새 글을 작성하여, 내 생각을 공유하고 싶다.
9. 작성자로서, 내 글을 수정하여, 잘못된 내용을 고치고 싶다.
10. 작성자로서, 내 글을 삭제하여, 더 이상 노출되지 않게 하고 싶다.
11. 관리자로서, 임의의 글을 수정·삭제하여, 부적절한 글을 정리하고 싶다.
12. 회원으로서, 글에 댓글을 작성하여, 의견을 남기고 싶다.
13. 회원으로서, 특정 댓글에 대댓글(1단계)을 작성하여, 그 댓글에 답하고 싶다.
14. 작성자로서, 내 댓글·대댓글을 수정하여, 표현을 고치고 싶다.
15. 작성자로서, 내 댓글·대댓글을 삭제하여, 내 발언을 거두고 싶다.
16. 관리자로서, 임의의 댓글·대댓글을 삭제하여, 부적절한 댓글을 정리하고 싶다.
17. 회원으로서, 글에 추천을 눌러, 호감을 표시하고 싶다.
18. 회원으로서, 이미 추천한 글의 추천을 다시 눌러 취소하여(토글), 마음을 바꿀 수 있게 하고 싶다.
19. 회원으로서, 댓글·대댓글에도 추천·취소(토글)하여, 좋은 댓글을 응원하고 싶다.
20. 회원으로서, 내가 작성한 글·댓글에는 추천할 수 없어, 자기 추천이 막힘을 알고 싶다.
21. 방문자로서, 글·댓글의 추천수를 확인하여, 반응 정도를 가늠하고 싶다.
22. 회원으로서, 글 상세를 열람할 때 조회수가 24시간에 1회만 오르게 하여, 조회수가 과장되지 않게 하고 싶다.
23. 방문자로서, 비로그인 상태로 글을 열람하면 조회수가 오르지 않아, 회원 기준 지표가 유지됨을 알고 싶다.
24. 방문자로서, 소프트 삭제된 글이 목록·상세에서 보이지 않아, 삭제된 글을 마주치지 않고 싶다.
25. 방문자로서, 소프트 삭제된 댓글이 보이지 않되 그 대댓글은 남아, 대화 맥락이 유지되길 바란다.
26. 미인증 사용자로서, 작성·수정·삭제·추천 시 로그인 페이지로 안내받아, 인증이 필요함을 알고 싶다.
27. 운영자로서, 앱 최초 기동 시 샘플 회원 5명·글 5개·댓글 5개가 생성되어, 빈 화면 없이 기능을 확인하고 싶다.
28. 운영자로서, 이미 회원이 존재하면 샘플 데이터 생성이 중단되어, 중복 시드가 일어나지 않길 바란다.

## Implementation Decisions

### 프로젝트/인프라
- `back/` 폴더에 Spring Boot 4.0.6, JDK 25, Gradle Kotlin DSL로 구성.
- 루트 패키지 `com.back`, 메인 클래스 `com.back.BackApplication`에 `@EnableJpaAuditing`.
- 의존성: Spring Web/MVC, Thymeleaf, thymeleaf-layout-dialect, Spring Data JPA, Validation, Spring Security, Lombok, DevTools, H2.
- OSIV 끄기(`spring.jpa.open-in-view: false`). 트랜잭션은 컨트롤러(액션) 메서드 레벨 `@Transactional`.
- 프로파일: 개발(`application.yml` + `application-dev.yml`, 파일 DB `./db_dev.mv.db`, ddl-auto update), 테스트(`application.yml` + `application-test.yml`, H2 in-memory, ddl-auto create). H2 콘솔 사용.
- 뷰: 타임리프 + layout-dialect 공통 레이아웃. 테일윈드 4.x Play CDN, DaisyUI 5 CDN, Pretendard 다이나믹 서브셋 웹폰트.

### 도메인 모델
- `BaseEntity`: `id`, 생성일시(`createDate`)·수정일시(`modifyDate`) 감사 필드. 모든 엔티티가 상속.
- `Member`: `username`(유니크, 로그인 ID), `password`(해시 저장), `nickname`, `role`(`USER`/`ADMIN`).
- `Post`: 작성자(Member), `title`, `content`, `viewCount`(정수), `deleted` 플래그.
- `Comment`: 작성자(Member), 소속 `Post`, `content`, 부모 `Comment`(nullable, 최상위면 null), `deleted` 플래그. 대댓글은 부모가 최상위 댓글일 때만 허용(1단계).
- `Recommendation`: 추천한 Member + 대상. 대상은 Post 또는 Comment. 한 회원이 한 대상에 0/1개(유니크 제약). 추천수 = 대상의 Recommendation 개수.
- `PostViewLog`(또는 동등): (Post, Member, 마지막 조회시각). 회원·글 단위로 마지막 조회시각을 추적, 24시간 시간창 판단에 사용.

### 추천(Recommendation)
- 토글: 없으면 생성(+1), 있으면 삭제(-1).
- 본인이 작성한 글·댓글에는 추천 불가(검증 후 거부).
- 글·댓글 양쪽에 동일하게 적용.

### 조회수(ViewCount)
- 로그인 회원이 글 상세 진입 시: 해당 회원의 마지막 조회시각이 없거나 24시간 초과면 `viewCount` +1 후 조회시각 갱신, 아니면 증가 없음.
- 비로그인 진입은 증가하지 않음.
- OSIV 꺼진 상태이므로 조회 + 증가를 상세 조회 액션 메서드의 단일 트랜잭션 안에서 처리.

### 권한(Role)
- Spring Security 폼 로그인 + 세션 기반.
- 글·댓글 수정·삭제: 작성자 본인 또는 `ADMIN`만 허용.
- 작성·추천: 인증 필요. 미인증은 로그인으로 리다이렉트.
- 비밀번호는 인코더로 해시 저장(평문 금지).

### 삭제(소프트 삭제 — ADR-0001)
- 글·댓글 삭제는 `deleted=true` 플래그만 설정.
- 모든 조회(목록·상세·추천수·조회수 집계·페이징)는 `deleted=false`만 대상.
- 글 소프트 삭제 시 댓글·대댓글 유지(글이 가려져 접근 경로 없음). 댓글 소프트 삭제 시 그 대댓글 유지.

### 목록/페이징
- 글 목록은 작성일 역순(최신순), Spring Data `Pageable`로 페이지 단위(예: 10개).

### 초기 데이터
- `com.back.global.initData.BaseInitData`에 `baseInitDataApplicationRunner` 빈(`@Transactional`).
- 회원이 1명이라도 있으면 시드 중단. 없으면 회원 5명·글 5개·댓글 5개 생성. 회원 중 최소 1명은 `ADMIN`.

### 페이지(라우트 개요)
- 회원가입, 로그인, 내 정보(nickname·password 수정), 글 목록, 글 상세, 글 작성/수정/삭제, 댓글 작성/수정/삭제(대댓글 포함), 글·댓글 추천 토글.

## Testing Decisions

- **좋은 테스트의 기준**: 구현 세부가 아니라 외부 동작(HTTP 요청 → 응답 상태/리다이렉트/모델·DB 상태 변화)을 검증한다. 서비스 내부 메서드 호출 횟수 등 내부 구조를 단언하지 않는다.
- **시봉(seam)**: 최상위 시봉인 **컨트롤러 HTTP 엔드포인트**를 통해 테스트한다. `@SpringBootTest` + `MockMvc`(test 프로파일, H2 in-memory, ddl-auto create)로 실제 스택(보안·JPA·트랜잭션 포함)을 관통. 새 시봉은 만들지 않는다.
- **대상**: 회원가입/로그인/내 정보 수정, 글 CRUD, 댓글·대댓글 CRUD, 추천 토글(본인 추천 거부 포함), 조회수 24시간 규칙(비로그인 미카운트 포함), 소프트 삭제 가시성(삭제 글·댓글 비노출, 대댓글 유지), 권한(작성자/ADMIN 외 수정·삭제 거부, 미인증 리다이렉트), 페이징.
- **prior art**: 신규 레포라 기존 테스트 없음. Spring Boot MockMvc 통합 테스트 컨벤션을 표준으로 삼아 첫 테스트들이 이후의 prior art가 된다.

## Out of Scope

- 회원 탈퇴, 비밀번호 찾기/재설정, 이메일 인증.
- 삭제된 글·댓글 복구 UI(소프트 삭제로 데이터는 남지만 복구 화면은 제공 안 함).
- 검색, 카테고리/태그, 첨부파일·이미지 업로드.
- 알림, 신고, 차단, 페이지네이션 외 정렬 옵션(인기순 등).
- REST/JSON API(서버 렌더링 페이지 전용).
- 비로그인 조회수·세션 기반 유니크 조회.

## Further Notes

- 추천수·조회수는 집계 시 매번 count 쿼리로 계산하거나 비정규화 카운트를 둘 수 있다 — 정확성 우선이면 count, 성능 우선이면 비정규화. 본 PRD는 정확성을 기본으로 하되 구현 단계에서 선택 가능.
- ViewCount 추적 테이블(`PostViewLog`)은 회원·글 조합당 1행을 유지하며 마지막 조회시각만 갱신하는 방식을 기본으로 한다.
